Entry8 전용 규칙:

- Entry8은 `01 FF <u16 char_count>` counted script line 구조다.
- ROM 적용용 `records[]`는 분리되어 있어야 하지만, 번역/검수는 `source_text` 단위로 문맥을 같이 본다.
- 원문에 없는 임의 줄바꿈을 추가하지 않는다.
- 일본어/한자 자체를 제외한 원문 특수기호와 문장부호는 유지 우선이다. Entry8은 반각 사용 불가 계열로 보고, 원문이 반각 기호여도 같은 의미의 전각 기호로 보존한다. `・`, `／`, `：`, `①`, `！`, `？`, `・・・` 같은 기호는 길이 부족이나 Entry8 렌더러 제약이 확인될 때만 최소한으로 바꾼다.
- `fixed_slot` / `candidate_repoint_keep_conservative`:
  - 반드시 `records[].max_korean_chars` 이하로 번역한다.
  - 단순히 짧게 줄이는 것이 목표가 아니다. 허용된 `max_korean_chars`를 가능한 한 활용해 의미, 말투, 조사, 목적어를 보존한다.
  - 예를 들어 사용 가능한 길이가 10자인데 5자로도 들어간다는 이유만으로 의미를 덜어내지 않는다.
  - 다만 제한을 넘기면 적용이 스킵될 수 있으므로, 최종 번역은 반드시 제한 이하여야 한다.
  - 의미 없는 padding, 불필요한 장식어, 원문에 없는 설명을 넣어 길이를 채우지는 않는다.
- `confirmed_repoint`:
  - 길이 제한을 크게 의식하지 말고 자연스러운 의미 보존을 우선한다.
- 여러 줄 unit은 하나의 발화/문맥으로 보고 자연스럽게 번역한 뒤, `records[]` 순서대로 다시 나눠 넣는다.
- 짧은 접두 조각 예:
  - `は、\n腹へったぁ…` -> `하,\n배고파...`
  - `兄さん、` -> `형,`
  - `アル、` -> `알,`
- Entry8 렌더러는 반각 공백/반각 기호가 불안정하므로 반각을 쓰지 않는다. 빌드 정규화가 공백/숫자/구두점을 전각으로 맞춘다.

작업 완료 조건:

- 담당 JSON 파일의 모든 `units[].translation_text`를 채운다.
- 모든 `units[].records[].translation`을 채운다.
- `fixed_slot` / `candidate_repoint_keep_conservative`는 `max_korean_chars` 이하로 맞추되, 가능한 한 원문 의미와 말투를 살릴 만큼 허용 길이를 활용한다.
- 상태 `status`를 `translated_length_checked`로 바꾼다.
- 다른 파일은 수정하지 않는다.
