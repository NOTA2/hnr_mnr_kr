# External Path Audit

Date: 2026-06-02 KST

This audit separates harmful external dependencies from harmless historical
provenance. The repo should stay self-contained except for explicitly local-only
inputs such as original ROMs, patched ROMs, save states, and emulator binaries.

## Policy

- Active scripts should derive repo paths from their own location or accept paths
  as arguments.
- Final tracked manifests should prefer repo-relative paths.
- Historical reports may contain absolute paths when the path is evidence of how
  an experiment was run.
- Cleanup should not erase path evidence before the related lesson is summarized
  in `docs/retrospective/`.
- Nothing in the final workflow should depend on `~/.codex`, `/private/tmp`, or
  `/Users/user/Downloads`.

## Active Script Findings

These are candidates for later cleanup, not immediate blockers.

- `scripts/build_startup_intro_from_atlas.sh`
  - Fixed in the structure pass: the script now computes `ROOT` from its own
    location and no longer embeds `/Users/user/test`.
- `scripts/run_mgba_runtime_probe.sh`
  - It correctly computes `ROOT`, but `find_mgba` also searches
    `$HOME/Downloads`.
  - Safer fix: keep explicit `MGBA_BIN` support and normal app locations, and
    decide whether Downloads probing belongs in a local-only helper.
- `scripts/apply_common_hud_korean_slot_patch.py`,
  `scripts/apply_battle_hud_name_font.py`, and
  `scripts/build_localization_workbench_dataset.py`
  - These use `/System/Library/Fonts/Monaco.ttf` for tiny debug labels.
  - This is not a project-data dependency, but final portability would be better
    with a small fallback chain or default PIL font.
- `scripts/build_translation_workspace.py`
  - Fixed in the structure pass: generated README links now use relative links.

## Historical / Provenance Findings

These should not be treated as active dependencies by default.

- `docs/` contains many absolute links into `/Users/user/test/...`.
  - Most are Markdown convenience links to files inside this repo.
  - Cleanup option: convert active documentation to relative links after the
    file layout stabilizes.
- `analysis/` contains many absolute paths from generated reports and old
  experiment logs.
  - This is expected for historical evidence.
  - Because `analysis/` is already ignored but still partly tracked, cleanup
    should first decide which analysis summaries to preserve.
- `confirmed_data/image_inventory/*_info.json` and report JSON files often
  record ROM, savestate, upload, or `/private/tmp` paths.
  - Treat these as provenance unless active GUI or build data reads them as
    required inputs.
- `confirmed_data/image_inventory/edit_packs/card_page_count/*_report.json`
  includes `/Users/user/Downloads/...` source images.
  - These are especially useful retrospective evidence because they explain the
    user-supplied asset lineage.

## Current Risk Ranking

- High: active JSON references to ignored
  `confirmed_data/localization_workbench/uploaded_image_replacements/` files.
  If those files are needed for final build/apply, they need promotion or clear
  local-only documentation.
- Medium: local convenience assumptions in active scripts, such as `$HOME/Downloads`
  emulator probing and fixed macOS debug label fonts.
- Medium: generated docs with absolute links.
  They make the repo feel machine-bound but usually do not break execution.
- Low: historical report paths under `analysis/` and runtime capture manifests.
  Keep or summarize based on retrospective value.

## Cleanup Order

1. Promote or document active uploaded image replacement assets.
2. Remove hard-coded `/Users/user/test` from active scripts.
3. Convert active docs generated by current tooling to repo-relative links.
4. Preserve retrospective lessons from historical reports.
5. Remove or untrack redundant generated evidence only after steps `1-4`.
