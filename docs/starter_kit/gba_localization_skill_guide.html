01

3분 안에 시작하기

스타터킷이 들어 있는 저장소 루트에서 Codex를 열고 아래 순서대로 진행합니다. 원본 ROM 자체는 로컬에만 두며 Git에는 절대 추가하지 않습니다.

초기화 명령 만들기

입력값은 이 브라우저 밖으로 전송되지 않습니다.

1. 라이프사이클 스킬 호출

$gba-localization-lifecycle

Codex 대화 입력창에 붙여 넣습니다. 터미널 명령이 아닙니다.

2. 저장소 제어 파일 초기화

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py init --root . --name 'my-gba-ko' --target-language ko --source-rom 'local_roms/source.gba'

이 명령은 .gba-localization/ 아래에 프로젝트 설정, 단계 상태, 검증용 매니페스트와 회고 기록 공간을 만듭니다.

3. 현재 상태 검사

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py check --root .
python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py status --root .

첫 검사에서는 미완료 항목이 나오는 것이 정상입니다. 오류 문구가 곧 다음 작업 목록입니다.

라이프사이클 스킬의 역할

지금 어느 단계인지 판단하고, 필요한 전문 스킬을 선택하고, 선행 조건과 종료 조건을 검사합니다. 실제 텍스트·폰트·이미지 작업은 각 단계 스킬이 담당합니다.

03

단계별 사용법

각 행을 열면 그 단계에서 해야 할 일, 저장해야 할 증거, 다음 단계로 넘어가기 위한 기준을 볼 수 있습니다.

01 프로젝트 기준선 gba-localization-bootstrap ROM 신원, 로컬 산출물 역할, 실행 명령, 저장소 경계를 확정합니다.

해야 할 일

  • 원본 ROM의 크기와 SHA-256 기록
  • ROM·세이브·캐시 Git 제외 검증
  • 모든 공개 명령을 저장소 루트 기준으로 통일
  • 입력·재생성 가능·보존 증거의 역할 분류

남길 증거

.gba-localization/project.json, .gba-localization/manifests/artifacts.json, 런타임 도구 목록, 기준 빌드 명령과 예상 출력 경로.

통과 기준

외부 컴퓨터의 절대 경로 없이 재현할 수 있고, Git 추적 대상과 로컬 전용 파일이 명확하며, 원본 ROM 해시가 실제 파일과 일치합니다.

02 ROM 구조 분석 gba-localization-rom-analysis 헤더, 포인터, 압축, 텍스트·이미지 후보를 보수적으로 조사합니다.

해야 할 일

  • 후보 영역과 레지스트리 목록화
  • 가설마다 최소 변경 실험 설계
  • 원본·실험 ROM 해시와 바이트 차이 기록
  • 실패한 가설도 이유와 함께 보존

남길 증거

조사 노트, 오프셋·포인터 표, 압축 판별 근거, 작은 패치 실험과 실행 결과. 추측은 반드시 가설로 표시합니다.

통과 기준

다음 단계가 사용할 구조적 가정이 최소 한 번의 재현 가능한 실험으로 검증되고, 미확정 영역은 빌드 규칙에 들어가지 않습니다.

03 텍스트 파이프라인 gba-localization-text 텍스트 계열별 경계·제어 바이트·포인터 계약을 보존하며 추출하고 다시 넣습니다.

해야 할 일

  • source family별 디코더와 적용 가능 범위 분리
  • 원본 바이트 span·종단자·제어 바이트 보존
  • 인접 레코드 겹침과 경계 검사
  • 미추출 일본어의 주변 printable island 조사

남길 증거

.gba-localization/manifests/text_sources.json, canonical text records, 추출·재적용 round-trip 결과, overlap·coverage 보고서.

통과 기준

추출된 모든 레코드가 원본 위치와 바이트 계약을 추적할 수 있고, 지원한다고 표시한 계열은 적용 후 구조 검사를 통과합니다.

04 한글 폰트와 인코딩 gba-localization-font 코드 공간, 글리프 저장 용량, 렌더러 주소 계산을 서로 분리해 검증합니다.

해야 할 일

  • 문자 코드와 글리프 슬롯의 수용량 산정
  • 폰트 타일 형식·폭·베이스 주소 확인
  • 필요 시 폰트 재배치와 포인터 수정
  • 대표 글자·희귀 글자·미니 폰트 실기 검증

남길 증거

.gba-localization/manifests/font.json, 코드 공간 표, 저장 배치, 렌더러 주소 근거, 아틀라스 이미지와 런타임 테스트 결과.

통과 기준

인코딩 가능한 문자 수와 실제 글리프 용량이 일치하고, 슬롯 충돌·합성 글자·폭 문제 없이 대표 문장이 게임 안에서 렌더링됩니다.

05 이미지 한글화 gba-localization-images 타일·타일맵·팔레트·압축의 출처를 추적하며 텍스트 이미지를 교체합니다.

해야 할 일

  • 화면이 아니라 ROM 리소스 단위로 대상 분류
  • 1x 편집 원본과 확대 미리보기 분리
  • 타일 순서·팔레트 provenance·crop map 기록
  • 공유 parent 수정 시 sibling 화면 회귀 검사

남길 증거

.gba-localization/manifests/image_targets.json, 대상별 원본·편집·삽입 payload, 매핑·팔레트 정보, 픽셀 diff와 런타임 캡처.

통과 기준

모든 대상이 현재 활성 소스를 가리키며, 압축·타일맵 구조 검증과 실제 화면 확인을 통과하고, 관련 sibling 화면이 깨지지 않습니다.

06 번역과 검수 gba-localization-translate canonical records를 기준으로 문맥·용어·잠금 상태를 추적하며 번역합니다.

해야 할 일

  • 용어집과 말투 원칙 먼저 고정
  • 문맥·화면·길이 제한을 workset에 포함
  • 초안·사람 검수·잠금 상태 분리
  • 중복 원문, 용어, 미번역, 길이 감사

남길 증거

.gba-localization/manifests/translation.json, source of truth 경로, workset 범위와 소유자, 잠금 통계, 일관성·레이아웃 감사 결과.

통과 기준

빌드가 참조하는 번역 필드가 하나로 명확하고, 우선순위 범위가 사람 검수를 거쳤으며, GUI·캐시·중간 JSON이 원본보다 앞서지 않습니다.

07 ROM 빌드와 게임 플레이 QA gba-localization-build-qa 같은 입력에서 같은 검수 ROM을 만들고 진행·저장·전환까지 실제로 확인합니다.

해야 할 일

  • 입력 해시·도구 버전·명령을 build manifest에 기록
  • 텍스트·폰트·이미지 적용 순서 고정
  • 메뉴, 전투, 이벤트, 저장, 화면 전환 검수
  • 버그마다 재현 절차와 수정 단계 연결

남길 증거

.gba-localization/manifests/qa_cases.json, build ID와 ROM 해시, 테스트 케이스·결과·스크린샷, 알려진 미검수 범위와 버그 기록.

통과 기준

최신 source of truth에서 검수 ROM이 재현되고, 출시 범위의 필수 케이스가 통과하며, 실패 항목은 원인 단계로 되돌아갈 수 있습니다.

08 패치 배포와 회고 gba-localization-release 원본 ROM 없이 패치를 검증하고, 정리 전에 재사용할 교훈을 보존합니다.

해야 할 일

  • 원본·결과 ROM 해시와 패치 생성 명령 기록
  • 깨끗한 원본에 패치를 다시 적용해 round-trip 검증
  • QA 범위, 알려진 문제, 자산 라이선스 문서화
  • 정리 후보를 역할·참조·재생성 가능성으로 판정

남길 증거

.gba-localization/manifests/release.json, 배포 패치와 해시, 적용 검증 결과, 릴리스 노트, 회고와 스타터킷 개선 제안.

통과 기준

패치만으로 검수 ROM이 정확히 재생성되고, 배포물에 ROM이 없으며, 삭제 전 게이트와 Git 체크포인트를 통과합니다.

04

상태는 진척도가 아니라 증거의 수준

“거의 된 것 같다”는 상태가 아닙니다. 각 단계의 매니페스트와 실제 파일이 의미 검사를 통과할 때만 ready 또는 complete로 올립니다.

상태 언제 사용하나 필수 기록 다음 행동
not_started 아직 작업과 조사가 시작되지 않음 없음 선행 단계와 현재 우선순위를 확인
in_progress 작업 중이며 결과가 아직 바뀔 수 있음 현재 증거와 짧은 작업 메모 claim 범위 안에서 증거를 계속 갱신
blocked 구체적인 선행 조건이나 외부 확인이 필요함 재현 가능한 blocker와 확인한 증거 막힘을 숨기지 말고 원인 단계로 이동
ready 다음 단계가 소비할 수 있는 결과가 준비됨 존재하는 저장소 상대경로 증거 check로 의미 게이트 통과 확인
complete 요구 범위와 종료 조건이 모두 충족됨 최종 증거, 검증 결과, 결정 메모 체크포인트 커밋 후 다음 단계 진행

작업 시작 체크포인트

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py checkpoint --root . --phase text --status in_progress --evidence .gba-localization/manifests/text_sources.json --note "dialog family extraction started"

막힘 기록

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py checkpoint --root . --phase text --status blocked --blocker "unknown command-stream terminator at 0x123456" --evidence localization/evidence/text/terminator_probe.md

단계 완료 체크포인트

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py checkpoint --root . --phase text --status complete --clear-blockers --evidence .gba-localization/manifests/text_sources.json --evidence localization/evidence/text/round_trip_report.md
빈 매니페스트로는 완료할 수 없습니다.

파일이 존재하는지만 검사하지 않습니다. 예를 들어 이미지 단계는 대상 목록, 활성 참조, 매핑·팔레트·런타임 증거가 채워져야 하고, QA 단계는 build ID와 실제 케이스 결과가 있어야 합니다.

05

여러 세션이 함께 일할 때

조사와 문서 읽기는 병행할 수 있지만, 매니페스트·생성물·ROM을 바꾸는 작업은 저장소 전체에서 한 번에 하나의 단계만 활성 claim을 가질 수 있습니다. claim은 이 단일 작성자 원칙을 기록합니다.

작업 범위 점유

단계와 소유자를 기록하고 만료 시간을 정합니다. 선행 단계가 준비되지 않으면 점유할 수 없습니다.

작업·검증·체크포인트

같은 owner 이름을 유지하고, 증거 파일과 상태를 갱신한 뒤 검사와 Git 체크포인트를 남깁니다.

점유 해제

다른 세션이 이어받을 수 있도록 claim을 해제합니다. 만료된 claim도 자동으로 무시하지 않습니다.

1. 이미지 단계 90분 점유

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py claim --root . --phase images --owner codex-images-01 --minutes 90

2. 상태와 현재 점유 확인

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py status --root .

3. 작업 후 점유 해제

python3 .agents/skills/gba-localization-lifecycle/scripts/lifecycle.py release-claim --root . --owner codex-images-01

병행해도 좋은 일

  • 문서와 기존 증거 읽기
  • 서로 다른 텍스트 workset의 번역 초안
  • 읽기 전용 ROM 후보 조사
  • QA 케이스 설계와 기존 캡처 비교

한 소유자만 해야 하는 일

  • 같은 단계 매니페스트 수정
  • 공유 parent 이미지나 팔레트 교체
  • canonical translation source 병합
  • 최종 ROM 빌드와 패치 생성
06

Codex에 이렇게 요청하세요

스킬 이름과 기대 결과를 함께 적으면 현재 저장소를 읽은 뒤 해당 절차로 작업합니다. 오프셋이나 구현 방식을 미리 단정하기보다 관찰할 증상과 완료 조건을 말하는 편이 좋습니다.

lifecycle

$gba-localization-lifecycle 현재 저장소의 단계 상태와 증거를 검사하고, 지금 해야 할 다음 작업을 결정해줘. 기존 파일은 삭제하거나 크게 옮기지 말고 먼저 위험을 보고해줘.

bootstrap

$gba-localization-bootstrap 이 저장소를 새 GBA 한글화 프로젝트의 안전한 기준선으로 초기화해줘. ROM 신원, Git 제외, 산출물 역할, 저장소 상대경로, 기준 명령을 검증해줘.

rom-analysis

$gba-localization-rom-analysis 이 ROM의 대화 텍스트 후보를 보수적으로 조사해줘. 추측과 검증된 사실을 분리하고, 작은 실험과 오프셋 증거를 남겨줘.

text

$gba-localization-text 아직 추출되지 않은 일본어를 source family별로 조사하고, record span·종단자·제어 바이트·포인터를 보존하는 추출 및 적용 경로를 만들어줘.

font

$gba-localization-font 현재 한글 폰트의 코드 공간, 글리프 용량, 타일 형식, 렌더러 주소 계산을 각각 검증하고 런타임에서 깨지는 글자의 원인을 찾아줘.

images

$gba-localization-images 이 메뉴 이미지의 ROM 리소스, 압축, 타일 순서, 타일맵, 팔레트 출처를 추적하고 1x 편집 원본과 런타임 검증까지 포함해 교체해줘.

translate

$gba-localization-translate 이 번역 workset을 용어집과 문맥에 맞게 검수해줘. 어색한 문장, 미번역, 중복 원문의 불일치, 길이 초과를 감사하고 canonical source만 갱신해줘.

build-qa

$gba-localization-build-qa 최신 번역·폰트·이미지로 검수 ROM을 재현 빌드하고, 메뉴·전투·이벤트·저장·화면 전환 QA 케이스와 결과 증거를 남겨줘.

release

$gba-localization-release 릴리스 후보의 패치 round-trip, 원본·결과 해시, QA 범위, 알려진 문제, 라이선스와 정리 게이트를 검증하고 회고 교훈을 스킬 개선안으로 정리해줘.

좋은 요청의 구조

스킬 이름 + 관찰한 증상 + 반드시 지킬 제약 + 기대하는 증거 순서로 씁니다. 예: “전투 승리 뒤 진행이 멈춘다 / 원본 ROM은 수정하지 않는다 / 재현 세이브와 적용 전후 해시를 남긴다.”

07

반드시 지킬 안전 규칙

이 규칙은 파일 정리, 구조 변경, 자동화, 여러 세션의 동시 작업에서 가장 먼저 적용합니다.

절대 하지 않는 일

  1. 01 ROM, 세이브, 세이브스테이트를 Git에 커밋하지 않습니다.
  2. 02 역할을 모르는 파일을 “임시 같아 보인다”는 이유로 삭제하지 않습니다.
  3. 03 스크린샷과 확대 미리보기를 편집 원본으로 승격하지 않습니다.
  4. 04 GUI 캐시나 중간 JSON을 번역 source of truth로 사용하지 않습니다.
  5. 05 다른 저장소나 개인 컴퓨터의 절대 경로를 활성 의존성으로 만들지 않습니다.
  6. 06 같은 공유 출력물을 여러 세션이 동시에 수정하지 않습니다.

삭제·이동 전 확인 순서

  1. 01 모든 문서와 매니페스트에서 참조를 검색합니다.
  2. 02 입력, 재생성 가능 산출물, 보존 증거, 로컬 런타임 파일 중 역할을 분류합니다.
  3. 03 canonical build와 GUI가 실제로 읽는 경로를 추적합니다.
  4. 04 대체 파일과 재생성 명령을 확인합니다.
  5. 05 작은 단위로 이동하거나 삭제하고 즉시 build·QA·Git diff를 확인합니다.
  6. 06 위험한 변경 전후로 커밋하고 원격 저장소에 푸시합니다.
정리보다 회고 증거가 먼저입니다.

실패한 실험, 임시 분석 스크립트, 오래된 이미지 payload도 재사용 가능한 교훈을 담고 있을 수 있습니다. 삭제 전에는 “왜 생겼고, 무엇이 대체하며, 같은 실수를 막을 규칙이 어디에 기록됐는가”를 확인합니다.

08

막혔을 때 보는 표

증상을 덮는 임시 패치보다 어느 단계의 계약이 깨졌는지 먼저 찾습니다. 아래 확인으로 해결되지 않으면 증거 경로와 함께 해당 전문 스킬을 호출합니다.

증상 먼저 확인 호출할 스킬
check가 실패한다 출력된 첫 의미 게이트, 누락된 저장소 상대경로, 선행 단계 상태를 순서대로 확인 $gba-localization-lifecycle
스킬이 목록에 보이지 않는다 저장소 루트에서 열었는지, .agents/skills/<name>/SKILL.md가 있는지 확인 후 작업을 다시 열어 목록 갱신 $gba-localization-lifecycle
원본 ROM이 없거나 해시가 다르다 잘못된 ROM으로 분석하지 말고 bootstrap을 blocked로 유지 $gba-localization-bootstrap
번역했는데 게임에는 일본어가 남는다 같은 화면 주변의 printable island, 다른 source family, GUI와 build source 불일치 조사 $gba-localization-text
한글이 합쳐지거나 엉뚱한 글자가 나온다 코드 공간과 글리프 슬롯 수, 렌더러 주소 계산, base pointer를 각각 확인 $gba-localization-font
이미지가 뒤섞이거나 색이 깨진다 타일·타일맵·팔레트의 공유 parent, 원본 1x 크기, 삽입 전후 픽셀 diff 확인 $gba-localization-images
GUI에서 수정한 내용이 ROM에 없다 GUI 저장 위치, canonical source, apply 입력 해시, 빌드 순서를 대조 $gba-localization-translate + $gba-localization-build-qa
진행 불가나 저장 오류가 생긴다 재현 세이브·입력 순서·직전 빌드 ID를 고정하고 구조 변경 단계로 되돌아감 $gba-localization-build-qa
claim이 만료되었거나 다른 owner가 잡고 있다 현재 Git 상태와 출력 해시를 비교합니다. 활성 claim은 기존 owner가 해제하고, 만료된 claim은 확인 후 새 owner가 재점유합니다. $gba-localization-lifecycle
패치를 적용한 ROM이 검수 ROM과 다르다 원본 해시, 패치 도구·명령, clean source에 대한 round-trip 결과 확인 $gba-localization-release
09

매 세션의 시작·작업·종료 루틴

오래 쉬었다 돌아오거나 다른 컴퓨터에서 이어갈 때도 아래 세 묶음만 지키면 현재 상태를 감으로 복원하지 않아도 됩니다.

시작할 때

  1. git status, branch, 최근 커밋 확인
  2. lifecycle.py check 실행
  3. lifecycle.py status로 다음 단계와 claim 확인
  4. 관련 문서·매니페스트·최근 증거 읽기

작업하는 동안

  1. 쓰기 전에 단계 claim 획득
  2. 작은 변경마다 구조 검사 또는 미리보기
  3. 실험 입력·명령·해시·결과 기록
  4. 실패를 숨기지 말고 blocker로 남기기

끝낼 때

  1. build·QA와 check 재실행
  2. phase checkpoint와 인수인계 메모 갱신
  3. claim 해제
  4. 의도한 파일만 커밋하고 push

세션 시작에 바로 붙여 넣을 요청

$gba-localization-lifecycle 이 저장소에서 이전 작업을 안전하게 이어가자. 먼저 git 상태, lifecycle check/status, 현재 claim, 최근 증거와 인수인계 문서를 읽고 실제 다음 단계를 보고해줘. 기존 변경은 되돌리지 말고, 쓰기 작업 전에는 해당 phase를 claim해줘.
완료의 정의

“ROM이 한 번 실행됐다”가 아니라, 깨끗한 입력에서 재현 가능하고, 필수 게임 플레이 범위를 통과하며, 패치 round-trip과 문서화가 끝났고, 다음 프로젝트에 넘길 교훈까지 남은 상태입니다.

이 문서는 저장소의 라이프사이클 스킬과 단계 계약을 사람이 빠르게 읽을 수 있도록 풀어쓴 가이드입니다. 명령 동작과 게이트의 최종 기준은 각 스킬의 SKILL.md와 실행 스크립트입니다.
