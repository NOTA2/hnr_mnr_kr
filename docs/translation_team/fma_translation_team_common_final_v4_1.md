# 강철의 연금술사 미주의 윤무곡 한국어 번역팀 공통 지침 v4.1

> 이 문서는 번역 에이전트와 검수 에이전트가 반드시 함께 참고해야 하는 공통 기준이다.  
> 역할별 작업 방식은 `fma_translation_agent_final_v4_1.md`, `fma_review_agent_final_v4_1.md`를 따른다.

---

## 0. 최우선 원칙

1. 원문에 없는 설정, 감정, 복선, 설명을 임의로 추가하지 않는다.
2. 작품 고유 용어와 인명 표기는 이 문서의 용어표를 우선한다.
3. 캐릭터 대사, 시스템 메시지, 기술 설명, 아이템 설명은 서로 다른 문체로 번역한다.
4. 한국어 플레이어가 실제 GBA RPG를 플레이할 때 자연스럽게 읽히는 문장을 목표로 한다.
5. 텍스트 박스 한계가 확정되지 않았으므로, 기본적으로 짧고 명확하게 번역한다.
6. 추출 JSON에 기존 `translation` 값이 있어도 기준으로 삼지 않는다. 임시 번역은 무시하고, 이 지침을 우선한다.
7. 깨진 문자열, 의미 없는 바이트 추출, 문자가 아닌 데이터로 보이는 값은 추측 번역하지 않는다.
8. 정발/공식 용례가 있는 원작 고유명사는 원작 용례를 우선하고, 게임 오리지널 고유명사는 제공된 『미주의 윤무곡』 PDF의 표기를 우선한다.

## 0.5 레이아웃 제약과 제어문자 규칙

현재 프로젝트에서 **객관적으로 확정된 것**과 **아직 미확정인 것**을 구분한다.

### 확정된 것

- 일부 텍스트는 일반 `00` 종단 문자열이 아니라, **고정 길이 슬롯** 안에 바로 들어간다.
- 대표 예시는 시작 화면 첫 카드 `4`줄이다.
  - 1줄: `6 bytes`
  - 2줄: `16 bytes`
  - 3줄: `18 bytes`
  - 4줄: `22 bytes`
- 이런 고정 길이 슬롯은:
  - 자동 줄바꿈이 없다.
  - 번역문 뒤에 `00 terminator`를 붙이면 안 된다.
  - 바로 뒤 제어코드를 밀어버릴 수 있으므로 **정확한 byte_length 안에 들어가야 한다.**
- 고정 길이 슬롯에서는 번역자가 임의로 `\n` 같은 강제 줄바꿈을 넣지 않는다.
- 현재 한글 폰트는 `가~힣` 완성형 기준으로 들어가며, 시작 화면에서는 한글 본체/그림자도 정상 매핑되도록 맞춘 상태다.
- 숫자, 영문, 기본 기호는 현재 기준으로 원본 게임 폰트를 재사용한다.

### 부분적으로 구조가 확정된 것

- save/menu 일부 텍스트는 일반 `00` 종단 문자열이 아니라 **`01 FF <u16 char_count>` command-stream 레코드** 다.
- 현재 대표 예시는 [save_menu_prefixed_texts.json](/Users/user/test/confirmed_data/extracted_texts/save_menu_prefixed_texts.json) 이다.
- 이 family 에서는:
  - `char_count` 헤더를 보존/갱신해야 한다.
  - 본문 뒤에 `00 terminator`를 임의로 붙이면 안 된다.
  - 본문 바로 뒤의 `10 FF`, `04 FF`, `14 FF`, `08 FF` 같은 제어코드를 밀면 안 된다.
  - 원문에 없는 임의 줄바꿈을 넣지 않는다.
- 세부 구조는 [text_box_family_manifest.json](/Users/user/test/confirmed_data/text_layout/text_box_family_manifest.json) 의 `save_menu_prefixed_01ff` family 를 따른다.
- Registry A entry `8` 대형 대사/이벤트 bank 도 일반 `00` 종단 문자열이 아니라 **`01 FF <u16 char_count>` counted script line** 구조다.
- 이 family 에서는:
  - `char_count` 헤더를 보존/갱신해야 한다.
  - 본문 뒤에 `00 terminator`를 임의로 붙이면 안 된다.
  - 본문 바로 앞뒤의 script control bytes 를 밀면 안 된다.
  - 원문에 없는 임의 줄바꿈을 넣지 않는다.
- 세부 구조는 같은 manifest 의 `entry8_prefixed_01ff_script_line` family 를 따른다.
- 현재 관측상 이 source 는 **explicit newline 없는 short single-line payload profile** 로 보는 편이 가장 안전하다.
- Registry D 이벤트/튜토리얼 대사는 일반 `00` 종단 문자열이 아니라 **`FC stop-byte` script line** 구조다.
- 이 family 에서는:
  - record boundary 를 `FC` 기준으로 유지해야 한다.
  - 본문 뒤에 `00 terminator`를 임의로 붙이면 안 된다.
  - 원문에 있던 명시적 개행은 보존 우선으로 본다.
  - `before_bytes / after_bytes` 로 대표되는 script control stream 을 밀지 않는다.
- 세부 구조는 같은 manifest 의 `registry_d_fc_stop_script_line` family 를 따른다.
- 현재 관측상 이 source 는 **explicit multiline payload profile** 이므로, 원문 개행 보존이 특히 중요하다.
- system message 일부는 일반 `00` 종단 문자열이지만, 이미 원문 안에 **명시적 개행(`\n`)** 이 들어 있다.
- 이 family 에서는 원문에 들어 있던 개행 수와 위치를 함부로 바꾸지 않는다.
- 세부 구조는 같은 manifest 의 `system_messages_plain_newline_00` family 를 따른다.
- `ui_skill`, `item`, `Registry A entry 12` 일부 gameplay term 은 **짧은 `00` 종단 plain record** family 로 부분 확정됐다.
- 이 family 에서는:
  - 번역문 뒤에 `00 terminator`는 공용 삽입기가 붙인다.
  - 원문에 없는 임의 줄바꿈을 넣지 않는다.
  - display family 가 아직 미확정이므로 짧고 보수적으로 번역한다.
- 세부 구조는 같은 manifest 의 `ui_or_item_plain_00_record` family 를 따른다.
- `battle`, `ability`, `material` 일부는 **`00` 종단 plain record + optional inline 0x0B separator** family 로 부분 확정됐다.
- 이 family 에서는:
  - embedded `0x0B` separator 와 전각 공백 패딩을 함부로 지우거나 바꾸지 않는다.
  - 원문에 없는 임의 줄바꿈을 넣지 않는다.
  - display family 가 아직 미확정이므로 짧고 보수적으로 번역한다.
- 세부 구조는 같은 manifest 의 `term_description_plain_00_optional_0b` family 를 따른다.
- credits 문자열은 **전각 공백 패딩을 가진 `00` 종단 plain record** family 로 부분 확정됐다.
- 이 family 에서는 padding 이 레이아웃 힌트 역할을 하므로, spacing-sensitive 수정은 매우 보수적으로 한다.
- 세부 구조는 같은 manifest 의 `credits_padded_plain_00_record` family 를 따른다.

### 아직 전역 확정되지 않은 것

- 일반 대사창의 `한 줄 최대 글자 수`
- 일반 대사창의 `한 박스 최대 줄 수`
- 화면군별 자동 줄바꿈 규칙
- `\n`, `[WAIT]`, `[PAGE]`, `{NAME}` 같은 제어 토큰의 실제 사용 범위
- `…`, `―`, `!`, `?`, `·`, `《》` 같은 문장부호의 전체 화면 호환성

### 현재 번역팀 운영 규칙

- 전역 수치가 확정되기 전까지는 “한 줄 14자” 같은 값을 임의로 상정하지 않는다.
- 원문에 명시된 줄바꿈/제어문자가 있으면 **보존 우선**으로 본다.
- 줄바꿈 정보가 없는 일반 대사는 짧고 명확하게 번역하되, 번역자가 임의로 과도한 줄나눔을 넣지 않는다.
- 길이 제약이 확정된 workset 은 별도 메모나 필드로 관리하고, 그 규칙이 있으면 그 규칙을 최우선한다.
- 화자 정보가 필요한 경우, 현재는 extracted JSON 안의 명시적 `speaker` 필드 대신 [confirmed_data/dialogue_metadata/README.md](/Users/user/test/confirmed_data/dialogue_metadata/README.md) 의 `dialogue_state_token` sidecar 를 먼저 참고한다.
- `dialogue_state_token` 은 확정 화자명이 아니라 **동일 portrait/state 후보를 묶는 객관적 제어 표식**으로만 취급한다.
- `entry8` 와 `Registry D` 는 둘 다 대사 source 지만 runtime profile 이 다르므로, 둘에 같은 줄바꿈 습관을 적용하지 않는다.

### 코드 기반으로 강하게 좁혀진 것

아래 값은 **실행 화면 전수 확인까지 끝난 하드 제한**은 아니지만, 현재 코드 분석상 매우 강한 후보다.
세부 근거는 [text_box_family_manifest.json](/Users/user/test/confirmed_data/text_layout/text_box_family_manifest.json) 을 따른다.
workset/source 연결은 [text_layout_assignment_index.json](/Users/user/test/confirmed_data/text_layout/text_layout_assignment_index.json) 을 따른다.
- high-priority dialogue profile 차이는 [runtime_dialogue_family_report.md](/Users/user/test/confirmed_data/text_layout/runtime_dialogue_family_report.md) 도 함께 본다.

- 공용 text object family 다수 caller (`0x062182`, `0x065AA4`, `0x06718A` 등) 는 모두 `r3=20` 으로 `0x014A98` 를 호출한다.
- 이 family 는 내부적으로 capacity `30` mixed-width units 로 변환된다.
- 코드상 현재 가장 강한 해석은:
  - fullwidth 문자 약 `20`자
  - halfwidth 문자 약 `30`자
- 월드맵 지역명 family (`0x06A972`) 는 `r3=12` 를 사용하고, capacity `18` units 로 변환된다.
- 코드상 현재 가장 강한 해석은:
  - fullwidth 문자 약 `12`자
  - halfwidth 문자 약 `18`자

주의:

- 위 수치는 번역 길이 감을 잡는 참고치다.
- 아직 일반 대사창 전 화면군에서 시각 QA까지 끝난 것은 아니므로, 번역팀은 이 값을 **절대 제한**처럼 단정하지 말고 우선 짧고 명확한 번역을 유지한다.

## 1. 작품 배경 요약

『강철의 연금술사 미주의 윤무곡』은 GBA용 RPG이며, 2003년판 애니메이션 계열의 설정과 분위기를 기반으로 한 외전성 작품이다.

- 무대는 연금술이 과학 체계로 성립한 군사국가 아메스트리스다.
- 연금술은 물질을 이해하고 분해·재구성하는 기술이며, 기본 원리는 등가교환이다.
- 에드워드 엘릭과 알폰스 엘릭은 과거 인체연성의 실패로 잃은 몸을 되찾기 위해 여행한다.
- 에드워드는 국가 연금술사이며, 별칭은 강철의 연금술사다.
- 알폰스는 영혼이 갑옷에 정착한 상태다.
- 이 게임에서는 키메라 사건, 소재와 기술 연성, 링커 및 게임 오리지널 인물 관련 사건이 중심이 된다.

배경지식은 번역을 자연스럽게 하기 위한 보조 정보다. 원문에 없는 배경 설명을 대사 안에 추가해서는 안 된다.

## 2. 고유명사와 띄어쓰기 원칙

### 2.1 기본 원칙

- 고유명사는 한국어 자연 띄어쓰기를 적용한다.
- 인명은 성과 이름을 띄어 쓴다.
- 지명 + 일반 명사도 띄어 쓴다.
- 계급과 직책은 인명 뒤에서 띄어 쓴다.
- 단, 이미 하나의 고정 명칭으로 굳은 용어는 용어표를 따른다.

예:

- `エドワード・エルリック` → `에드워드 엘릭`
- `アルフォンス・エルリック` → `알폰스 엘릭`
- `マスタング大佐` → `머스탱 대령`
- `ブラッドレイ大総統` → `브래드레이 대총통`
- `オルヘンティノス城` → `올헨티노스 성`

비권장:

- `에드워드엘릭`
- `알폰스엘릭`
- `머스탱대령`
- `브래드레이대총통`
- `올헨티노스성`

### 2.2 계급/직책 표기

| 원문 | 번역 |
|---|---|
| 大総統 | 대총통 |
| 大佐 | 대령 |

| 中尉 | 중위 |
| 少尉 | 소위 |
| 教主 | 교주 |
| 司令部 | 사령부 |

계급은 붙이지 않는다.

- 권장: `머스탱 대령`, `마틴스 중령`, `브래드레이 대총통`
- 비권장: `머스탱대령`, `마틴스중령`, `브래드레이대총통`

## 7. 시스템 메시지 문체 규칙

시스템 메시지는 캐릭터 대사가 아니라 게임 UI가 플레이어에게 전달하는 문장이다. 기본적으로 존댓말을 사용한다.

### 7.1 불가 / 오류 / 완료 / 결과 알림

공식적인 시스템 알림은 `~습니다` 체를 사용한다.

| 원문 | 권장 |
|---|---|
| セーブはできないぞ | 저장할 수 없습니다. |
| データ転送できませんでした | 데이터를 전송하지 못했습니다. |
| セーブしました | 저장했습니다. |
| アイテムが足りません | 아이템이 부족합니다. |

비권장:

- 저장할 수 없다
- 저장 못 해요
- 저장은 못 한다고!

### 7.2 확인 / 선택 질문

플레이어에게 선택을 묻는 문장은 `~까요?`를 우선 사용한다.

| 원문 | 권장 |
|---|---|
| 今までの旅をセーブするか？ | 지금까지의 여정을 저장할까요? |
| これまでの旅を記録する？ | 지금까지의 여정을 기록할까요? |
| 前のデータに上書きするぞ？ | 이전 데이터에 덮어쓸까요? |
| このまま旅を続けるか？ | 이대로 여행을 계속할까요? |

`~하시겠습니까?`는 길고 딱딱하므로 기본적으로 피한다. 단, 중요한 최종 확인이나 경고성 선택지에서는 허용한다.

### 7.3 진행 중 / 대기 / 상태 표시

진행 상태는 문장형보다 짧은 명사형을 우선한다.

| 원문 | 권장 |
|---|---|
| セーブ中だ… | 저장 중... |
| 通信中・・・ | 통신 중... |
| ロード中 | 불러오는 중... |

### 7.4 안내문

안내문은 `~주세요`, `~마세요`를 사용한다.

| 원문 | 권장 |
|---|---|
| ケーブルを確認してください | 케이블을 확인해 주세요 |
| 接続数を１台にしてください | 접속 수를 1대로 맞춰 주세요 |
| 電源を切らないでください | 전원을 끄지 마세요 |

### 7.5 시스템 메시지 마침표 기준

- 단독 문장형 알림은 마침표를 붙인다.
  - 예: `저장할 수 없습니다.`
- 2줄 이상의 짧은 UI 알림은 마침표를 생략할 수 있다.
  - 예: `통신 오류!\n데이터를 전송하지 못했습니다`
- 진행 상태에는 마침표를 붙이지 않는다.
  - 예: `저장 중...`

## 8. 캐릭터별 말투 기준

캐릭터 말투 예시는 정발 대사를 직접 인용한 것이 아니라, 정발/원작 용어와 캐릭터 성격, 제공된 게임 자료를 참고해 만든 프로젝트용 샘플이다.

### 8.1 에드워드 엘릭

- 기본 반말.
- 짧고 직설적.
- 자신감 있고 약간 거칠다.
- 설명할 때도 지나치게 공손하지 않다.
- `난`, `내가`, `~야`, `~지`, `~라고` 계열을 자연스럽게 사용한다.
- `젠장`, `쳇`, `뭐라고?` 정도는 가능하다.
- 현대적 욕설, 인터넷 밈, 과한 비속어는 금지한다.

예시:

| 원문 | 권장 방향 |
|---|---|
| さぁ相手になってやるぜ！ | 자, 상대해 주지! |
| 錬成であっさり終わらせる！ | 연성으로 단숨에 끝내 주지! |
| このコマンドで錬成だ！ | 이 커맨드로 연성이야! |
| とりあえず見とけ | 일단 보고 있어. |

### 8.2 알폰스 엘릭

- 기본은 부드러운 반말.
- 형에게는 `형`이라고 부른다.
- 타인에게는 상황에 따라 존댓말을 사용할 수 있다.
- 설명할 때는 차분하고 친절하다.
- 과하게 어린아이처럼 만들지 않는다.

예시:

| 원문 | 권장 방향 |
|---|---|
| 兄さん、どうやって戦うの？ | 형, 어떻게 싸우는 거야? |
| 素材や技を作るんだね | 소재나 기술을 만드는 거구나. |
| じゃあこれでいい素材をたくさん作ろうよ、兄さん | 그럼 이걸로 좋은 소재를 많이 만들자, 형. |
| 等価交換だね | 등가교환이네. |

### 8.3 로이 머스탱

- 군인답게 단정하고 냉정한 말투.
- 지나치게 가볍거나 장난스럽게 만들지 않는다.
- 부하에게는 명령형, 동료에게는 절제된 반말/존댓말을 문맥에 맞춰 사용한다.

### 8.4 리자 호크아이

- 절제되고 정중한 군인 말투.
- 감정을 과하게 드러내지 않는다.
- 명령·보고·경고는 간결하게 처리한다.

### 8.5 알렉스 루이 암스트롱

- 과장되고 장중한 말투.
- 다만 밈처럼 과하게 희화화하지 않는다.
- 문장이 길어지면 GBA 문장 길이에 맞춰 압축한다.

### 8.6 코니슈 로이스 / 코니

- 초반에는 밝고 상냥하며 정중한 말투.
- 후반에는 절망과 결의가 드러나지만, 원문보다 감정을 과하게 설명하지 않는다.
- 오빠 세라피 로이스와 관련된 정체/진상은 초반 대사에 선반영하지 않는다.

### 8.7 아스턴 마틴스

- 반항적이고 거친 면이 있지만 동료애가 강한 군인.
- 계급은 중령. `마틴스 중령`으로 표기.
- 죄수/탈옥/명령 불복 문맥에서는 다소 거친 반말을 허용하지만, 과한 현대 비속어는 금지한다.

### 8.8 링커 / 세라피 로이스

- 링커일 때는 차갑고 압박감 있는 말투.
- 설명을 과하게 늘리지 않는다.
- 위협·집착·냉소가 있는 대사는 짧고 날카롭게 처리한다.
- 세라피 로이스의 과거/본래 성격이 드러나는 장면은 비극성과 선의를 유지한다.

### 8.9 케이트 람

- 천진난만하지만 고집 세고 자존심 강한 말투.
- 어린아이 취급에 반발하는 성향을 살리되, 지나치게 유치하게 만들지 않는다.

### 8.10 랜디 로버

- 투박하고 단순한 말투.
- 힘은 세지만 상식이 부족한 느낌을 살린다.
- 과도한 비속어와 현대 밈은 금지한다.

## 13. 불확실한 항목 처리

- 원문 의미가 불확실하면 무리하게 멋을 내지 않는다.
- 기술명·소재명은 계열성을 우선하고, 판단이 어려운 경우 직역에 가깝게 둔다.
- 추출 데이터가 깨진 문자열처럼 보이면 번역하지 않고 검수 대상으로 남긴다.
- 확정되지 않은 고유명사는 기존 용어표를 따르되, `notes`가 허용될 경우 검토 필요 표시를 남길 수 있다.
